# Прототип Теготеки

Локально запускаемое браузерное приложение для проверки концепции и интерфейса Теготеки. Записи — тексты, изображения, аудио, видео и другие файлы — находятся по тегам. Данные сохраняются между запусками.

## Запуск

Нужен Node.js 20 или новее (проверено на 22) и современный браузер. Устанавливать зависимости для запуска не требуется.

```bash
npm start
```

После запуска откройте в браузере адрес <http://127.0.0.1:4173/>. Остановить сервер — `Ctrl+C` в том же окне терминала.

Если порт занят, задайте другой:

```bash
PORT=4180 npm start
```

В Windows PowerShell: `$env:PORT=4180; npm start`. Без npm то же самое делает `node server/server.mjs`.

Сервер принимает соединения только с этого компьютера (`127.0.0.1`).

## Данные

Данные хранятся в каталоге `data/` в корне проекта; он создаётся при первом запуске и не попадает в git. Другой каталог задаётся переменной `TEGOTEKA_DATA_DIR`.

| Путь | Содержимое |
| --- | --- |
| `data/workspaces/<id>/workspace.json` | Элементы, теги, описания тегов, разметка. |
| `data/workspaces/<id>/state.json` | Последний узел, история переходов, режим просмотра, сортировка, настройки. |
| `data/workspaces/<id>/files/` | Сами файлы содержания: изображения, аудио, видео и другие. |
| `data/app.json` | Последняя открытая рабочая область. |

Резервная копия — копия каталога `data/`. Чтобы начать с чистого листа, остановите сервер и удалите этот каталог.

Размер одного файла ограничен 200 МБ; предел меняется переменной `TEGOTEKA_MAX_FILE_MB`.

## Демонстрационный набор

При первом запуске приложение предлагает создать рабочую область и выбрать, чем её наполнить:

| Заготовка | Содержимое |
| --- | --- |
| Пустая | Без элементов и тегов. |
| Демонстрационный набор | Записи E0–E9 из [проверочных сценариев](prototype/CHECKS.md), тег `мечта` без элементов, описание тега `бюджет`. |
| Демонстрационный набор с медиа | Тот же набор и четыре элемента с файлами из `demo-media/`. |
| Диагностический набор | 10 000 коротких текстов и 100 тегов. |

Позже новая рабочая область создаётся так же: название области в шапке → «Новая рабочая область». Каждый проверочный сценарий, изменяющий данные, удобно начинать с новой копии демонстрационного набора.

Примеры медиа для добавления вручную лежат в `demo-media/`: изображение, аудиозапись, видеозапись и документ PDF. Их можно получить заново командой `npm run demo-media` (нужны ffmpeg и Playwright).

## Проверки

```bash
npm test
```

Автоматические проверки теговой модели, операций над данными, истории переходов и хранилища. Зависимости не нужны.

```bash
npm install
```

```bash
npx playwright install chromium
```

```bash
npm run test:browser
```

Сценарии из [проверки прототипа](prototype/CHECKS.md) в браузере Chromium. Каждый файл сценариев запускает отдельный сервер на случайном порту `127.0.0.1` с временным каталогом данных; рабочий каталог `data/` не затрагивается. Снимки экрана сохраняются в `e2e/artifacts/`.

```bash
npm run measure
```

Диагностическая проверка объёма на уровне модели: воспроизводимый набор, распределение тегов, время отбора, получения переходов и автодополнения.

Результаты выполненных проверок, известные ограничения и наблюдения — в [отчёте](prototype/REPORT.md).

## Устройство

| Каталог | Назначение |
| --- | --- |
| `shared/` | Теговая модель и операции над данными. Одни и те же модули работают на сервере, в браузере и в проверках. |
| `server/` | Локальный HTTP-сервер и хранилище на диске. |
| `public/` | Интерфейс: страница, стили, модули, библиотека отрисовки в `public/vendor/`. |
| `tests/` | Автоматические проверки модели и хранилища. |
| `e2e/` | Сценарии в браузере. |
| `scripts/` | Замер на диагностическом наборе и создание примеров медиа. |
| `demo-media/` | Примеры медиа. |
