# Импорт и экспорт

**Статус:** необязательное расширение.

**Родительский модуль:** [базовый продукт](../PRODUCT_CONCEPT.md).

**Обязательная зависимость:** базовый продукт, включая ручную разметку и список неразмеченных элементов.

Расширение подчиняется [соглашениям продукта с расширениями](../PRODUCT_EXTENSION_AGREEMENTS.md#общие-соглашения).

## Назначение и варианты переноса

**Экспорт** — передача данных из рабочей области.

**Импорт** — приём данных в рабочую область.

**Исходная рабочая область** — рабочая область, из которой передаются данные.

**Принимающая рабочая область** — рабочая область, в которую поступают данные.

Экспортированные данные должны быть пригодны для последующего импорта без обращения к исходной рабочей области.

Повторный импорт того же элемента распознаётся автоматически.

Расширение поддерживает перенос всей рабочей области или её части.

Экспорт всей рабочей области включает все её элементы и весь глоссарий тегов рабочей области.

При экспорте части рабочей области из текущего узла пользователь выбирает состав экспортируемых элементов:

- Только собственные элементы текущего узла.
- Выборку текущего узла.

При экспорте части рабочей области пользователь также выбирает состав тегов:

- Только теги экспортируемых элементов вместе с имеющимися поясняющими описаниями — вариант по умолчанию.
- Весь глоссарий тегов рабочей области.

При экспорте теговая разметка элементов сохраняется в экспортируемых данных.

## Названия при повторном импорте

Если название импортируемого элемента отличается от названия того же элемента в принимающей рабочей области, пользователю задаётся вопрос, какое название сохранить. Это правило действует независимо от происхождения названий и состояния разметки элемента.

Пользователь может решить отдельно для каждого элемента, какое название сохранить, либо применить одно решение ко всем различиям названий в текущем импорте: сохранить названия принимающей рабочей области или принять импортируемые.

## Разметка при импорте

Правила разметки применяются как при импорте всей рабочей области, так и при импорте её части.

Пользователь выбирает один из двух вариантов:

- **Сохранить глоссарий принимающей рабочей области.** Новые для неё элементы импортируются как неразмеченные и требуют назначения тегов этого глоссария. Разметка уже имеющихся элементов сохраняется; неразмеченные элементы остаются неразмеченными.
- **Заменить глоссарий принимающей рабочей области импортируемым.** Текущий набор тегов и их поясняющие описания заменяются импортируемыми. Новые для области элементы сохраняют импортируемую разметку. Уже имеющиеся элементы, которые не входят в импортируемые данные, требуют разметки по новому глоссарию.

Повторный импорт уже имеющегося элемента не создаёт копию. При замене глоссария для такого элемента пользователю предлагается выбор: принять импортируемую разметку или назначить теги нового глоссария заново.

При сохранении импортируемой разметки сохраняется и её состояние: неразмеченный элемент остаётся неразмеченным, а элемент с заданным пустым набором тегов остаётся размеченным.

Иные правила разметки новых элементов при совместной работе расширений задаются в [документах координации родительского модуля](README.md#координация).

### Предварительное сравнение объёма разметки

До выбора варианта и применения импорта пользователю показывается объём предстоящей разметки для обоих вариантов: общее число элементов, которым потребуется разметка после импорта, и отдельно число новых и уже имеющихся элементов среди них.

Каждый элемент учитывается один раз. В сравнении учитываются и исходно неразмеченные элементы, которым по-прежнему потребуется назначить теги.

Если объём разметки зависит от решения по совпадающим элементам, пользователю показывается, как каждый из вариантов решения влияет на этот объём. После выбора объём уточняется до применения импорта.

## Взаимодействие с разметкой

Элементы, которым требуется разметка в принимающей рабочей области, поступают в общий список неразмеченных для работы по [правилам базового продукта](../PRODUCT_CONCEPT.md#8-работа-с-элементами).

При разметке доступны исходные теги элемента и их поясняющие описания из прежнего глоссария. Это относится как к импортированным элементам, так и к элементам принимающей области при замене её глоссария.
