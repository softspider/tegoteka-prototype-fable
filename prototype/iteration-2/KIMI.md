## Замечания к существующей реализации

### Сохранение при работе в двух вкладках

Удаление тега использует снимок рабочей области из React, после чего `replaceWorkspace` очищает таблицы и записывает этот снимок. Если другая вкладка уже сохранила новую запись, устаревший снимок может её стереть. Механизм воспроизведён на уровне тех же функций хранилища с IndexedDB в памяти: количество уменьшилось с 11 до 10, новая запись исчезла.

Исправить сохранение так, чтобы удаление тега не теряло уже сохранённые элементы другой вкладки. Проверить сценарий с двумя вкладками одной изолированной рабочей области: открыть обе, во второй добавить запись, в первой удалить тег. После обновления обеих вкладок запись существует, удаление тега применено корректно. Исходные места проверки: `src/state/WorkspaceContext.tsx`, `src/data/db.ts`.

### История после удаления тега

`src/state/useNavigation.ts` удаляет тег из всех прежних посещений, превращая их в другие узлы. История должна сохранять посещения и пропускать недоступные узлы.

Проверить маршрут: корень → `{ремонт}` → `{ремонт, кухня}` → создание записи `{сад}` и переход к её узлу → удаление тега `ремонт` → «Назад». Результат — корень, а не непосещённый `{кухня}`. Проверить также сохранение доступной части истории и отсутствие новых посещений от самого удаления тега.

### Переход после разметки

После сохранения разметки из отдельного режима нет предложения перейти в собственный узел элемента; оно также подавлено при полном редактировании из этого режима. В обычном редакторе предложение есть, но теги узла назначения не показаны.

Для каждого пути сохранения проверить правило концепции: текущий узел остаётся прежним; если собственный узел сохранённого элемента другой, пользователь видит его теги и предложение перейти. Сам переход происходит по выбору пользователя. Исходные места проверки: `src/components/MarkingMode.tsx`, `src/App.tsx`.

### Просмотр нового медиа при редактировании

После выбора нового файла `src/components/ElementEditor.tsx` оставляет только имя файла. Обеспечить доступ к выбранному содержанию при корректировке тегов до сохранения.

Проверить создание и замену изображения, аудио и видео: выбранное содержимое доступно для просмотра или воспроизведения, при этом показанное содержимое соответствует новому файлу.

## Проверка интерфейса

В прежней версии на экране `1440×1000` навигация занимала почти весь первый экран. При переработке оценивать её доступность вместе с обозримостью результата по новым правилам. Проверять смартфонную компоновку с тем же приоритетом навигации и создания; простое уменьшение прежней вертикальной страницы не доказывает выполнение Mobile First.
