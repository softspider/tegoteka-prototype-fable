## Исправления замечаний

### Параллельное сохранение состояния просмотра

**Воспроизведение.** Проверка `tests/state-saving.test.mjs` на коде первой итерации: 20 одновременных `saveState` — одно успешное, 19 с ошибкой `ENOENT` при переименовании общего временного файла. Совпадает с описанием в задании.

**Исправление.** Каждая запись использует собственное временное имя; записи одного файла выполняются по очереди. Состояние несёт отметку времени клиента, и сервер не заменяет более новое состояние более старым. `open` ставит запись последней области в очередь сразу, поэтому порядок записей следует порядку открытий. Браузер отправляет состояние по одному запросу, досылает последнее, а при неудаче показывает предупреждение и повторяет попытку.

| Проверка | Результат |
| --- | --- |
| 20 одновременных `saveState` | Все успешны; файл — корректный JSON с последним состоянием; временных файлов не осталось |
| Перекрывающиеся сохранения в обратном порядке отметок | Сохранено самое новое; более старые отклонены без ошибки |
| Перезапуск хранилища | Отметка читается с диска; состояние первой итерации без отметки сохраняется |
| `setLast`: 20 одновременных открытий двух областей | Все успешны; `app.json` корректен и указывает область последнего открытия |
| Оба пути вместе: `saveState`, `open` и `setLast` одновременно | Все 30 операций успешны; состояние — последнее |
| HTTP: 20 одновременных и 20 быстрых последовательных `PUT`, перезапуск сервера | Все ответы 200; после перезапуска — последнее состояние; 10 элементов на месте |
| Браузер: 42 изменения подряд без пауз и немедленная перезагрузка | Восстановлен последний переход; отправлено меньше запросов, чем изменений, по порядку |
| Браузер: сервер отвечает ошибкой на сохранение | Видно предупреждение «Состояние просмотра не сохранено»; после устранения сбоя — сохранение по кнопке и автоматически |

Содержание элементов этими сценариями не затрагивалось и не терялось.

### Описание нового тега при немедленном сохранении

**Исправление.** Теги, набранные в поле и не подтверждённые, входят в сохраняемый набор. Если среди них есть новые, первое нажатие «Сохранить» добавляет их в набор и показывает поля описаний с фокусом в первом; сохраняет следующее нажатие.

| Проверка | Редактор элемента | Режим разметки |
| --- | --- | --- |
| Новый тег набран без Enter, нажато «Сохранить» | Форма открыта, описание предложено, ничего не сохранено | То же; элемент остаётся неразмеченным |
| Описание введено, повторное сохранение | Тег и описание в глоссарии | Тег и описание в глоссарии |
| Описание пропущено, повторное сохранение | Тег сохранён без описания | Тег сохранён без описания |
| Существующий тег набран без Enter | Сохранение одним нажатием | — |
| Подтверждённый существующий и неподтверждённый новый | Описание предложено только новому | — |
| Тег подтверждён Enter | Поле описания видно заранее, сохранение одним нажатием | — |
| Изменение существующего элемента | Описание предложено | — |

По ходу найдено и исправлено: список подсказок при неподтверждённом вводе заслонял кнопку сохранения в режиме разметки и мог заслонять кнопки диалога.

### Быстрый Escape после открытия диалога

**Причина.** Обработчик клавиш подключался в отложенной фазе после отрисовки: окно уже было видно, но ещё не слушало клавиатуру.

**Исправление.** Один обработчик окна подключён при загрузке приложения; диалог регистрируется синхронно с появлением в документе. Искусственных задержек в проверках нет.

| Проверка | Результат |
| --- | --- |
| Escape отправляется в момент появления окна в документе: глоссарий, настройки, рабочие области, форма элемента — по три раза | Окно закрывается все 12 раз |
| Фокус после закрытия | Возвращается на кнопку, открывшую окно |
| Щелчок и сразу Escape с клавиатуры, 10 раз | Окно закрывается все 10 раз |
| Последующая работа | Фильтр глоссария, Tab внутри окна, переход в узел — действуют |
| Несохранённые изменения в форме | Escape форму не закрывает и сообщает об изменениях |
| Вложенное окно | Escape закрывает только верхнее |

Тем же способом найден и исправлен такой же дефект в меню карточки: Escape сразу после открытия меню его не закрывал.

## Новые правила показа

Данные: набор E0–E9, четыре элемента с медиа и пять элементов с одинаковой разметкой `{сад}` — короткие и длинный тексты, два одинаковых названия, одно отсутствующее. В узле `{сад}` шесть собственных элементов и семь в выборке. Для вместимости экрана — отдельная область: по четыре коротких и длинных текста, очень длинный текст, изображение.

### Предел количества

| Проверка | Собственные элементы | Выборка узла |
| --- | --- | --- |
| `N` элементов, затем `N+1` | `N=6`: показаны 6; после добавления скрыты 7 | `N=7`: показаны 7; после добавления скрыты 8 |
| Удаление элемента без перехода | Показ возвращается | Показ возвращается |
| Изменение предела в настройках | `N−1` скрывает, `N` показывает | То же |
| Сужение и расширение тегов, `N=4` | — | Корень 18 скрыто → `{ремонт}` 6 скрыто → `{ремонт, кухня}` 4 показаны → обратно скрыто |
| Собственных мало, выборка больше `N` | `{ремонт}`: 1 показан | 6 скрыты; действует количество выборки |
| Скрытое и пустое, `N=1` | `{ремонт, кухня}`: «нет собственных элементов» | Корень: «Скрыто элементов: 18»; `{мечта}`: «Нет элементов с выбранными тегами» при всех трёх способах |

### Оценка

Порядок доступа соответствует приоритетам: навигация и создание доступны одним нажатием из любого места страницы; изменение — одним нажатием на видимой карточке; способы отображения — над списком; настройки — в верхней строке, которая прокручивается вместе со страницей.

Дополнительно проверено на обоих размерах: форма создания и изменения показывает кнопки при уменьшенной до 55 % высоте окна; 30 переходов с длинными тегами дают компактный набор, фильтр и страницы; восемь выбранных длинных тегов занимают не больше 45 % высоты окна, поле ввода остаётся видимым и после добавления девятого; ни один экран не требует прокрутки вбок. Области нажатия на смартфоне — не меньше 32 пикселей по высоте.

Постоянных обучающих текстов нет. Остались названия действий, сообщения о состоянии, подтверждения удаления и напоминание о соответствии тегов содержанию.

Найденные неудобства исправлены, затронутые сценарии повторены:

| Неудобство | Исправление |
| --- | --- |
| Карточка на смартфоне занимала лишнюю строку: четыре коротких элемента не помещались на экране | Теги и действия стоят в одной строке |
| Поле ввода тега скрывалось за длинным набором выбранных тегов | Поле закреплено у нижнего края панели |
| Список подсказок на смартфоне выходил за правый край | Занимает ширину окна |
| Список подсказок заслонял кнопки формы | Заканчивается над кнопками; в режиме разметки открывается вверх |
| Запрос крайних позиций оставался активным, когда множество уже показано целиком | Запрос снимается |
| Название следующего тега в глоссарии стиралось ответом на предыдущее добавление | Форма очищается сразу при отправке |

## Диагностика объёма

Набор прежний: 10 000 элементов, 100 тегов, зерно 20261111. Модель не менялась; отбор в корне — 0,45 мс, переходы — 35,5 мс, сортировка по названию — 11,4 мс (медианы `npm run measure`).

Интерфейс, время от события до второго кадра: выбор выборки корня со скрытыми 10 000 элементами — 18 мс; первые и последние пять — 21–26 мс; страница — 26 мс; последняя из 1 000 страниц — 32 мс; показ по вместимости экрана — 31 мс, заведомо не помещающееся множество не строится; добавление элемента с записью на диск — 130 мс. Задач дольше 50 мс не зафиксировано.

## Оставшиеся ограничения

- На смартфоне переходы-плашки прокручиваются вместе со страницей. Закреплены ввод тегов, история и корень; чтобы нажать предложенный переход из глубины длинной страницы, нужно вернуться к началу.
- Способ «по вместимости экрана» считает область при непрокрученной странице. Чем больше переходов и выбранных тегов над списком, тем меньше элементов помещается; на смартфоне это от трёх до пяти коротких записей.
- Номер страницы и запрос крайних позиций не сохраняются между запусками и сбрасываются при смене узла.
- Вторая вкладка с той же областью не обновляется сама; её состояние просмотра сохраняется по правилу «новее по времени».
- Ограничения первой итерации по объёму данных, форматам файлов и одному пользователю сохраняются.

## Вопросы к концепции

Эти места решены в прототипе допущениями из [решений](DECISIONS.md); смысл продуктового поведения они не меняют, но заслуживают подтверждения.

1. **Доступная область для способа «по вместимости экрана».** Концепция говорит о «доступной для них области экрана». В прототипе это область от начала списка до нижнего края окна при непрокрученной странице. Альтернатива — считать от закреплённой панели узла, то есть допускать, что переходы прокручены.
2. **Экранная клавиатура.** В прототипе она не уменьшает доступную область, иначе список скрывался бы во время ввода тега.
3. **Крайние позиции.** Не определены число элементов и срок действия запроса. В прототипе — пять элементов, до смены узла, состава или способа показа.
4. **Сортировка при запрошенных крайних позициях.** Концепция говорит только, что сортировка сама их не включает. В прототипе уже запрошенные крайние позиции пересчитываются по новой сортировке.
5. **Изменение скрытых элементов.** При скрытом множестве изменить элемент можно только через крайние позиции или страницы. Это следствие правила обозримости; стоит подтвердить, что так и задумано для третьего приоритета.
6. **Название репозитория.** В дополнении указан `aiaiai-copilot/tegoteka-prototype-fable`; фактический репозиторий реализации — `softspider/tegoteka-prototype-fable`.
